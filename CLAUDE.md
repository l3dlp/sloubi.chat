# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Sloubi.chat: multi-room real-time chat (Go + Gin + SQLite) with a vanilla-JS PWA frontend. Each room lives at `sloubi.chat/<chan>` and has a shared post-it and one of three themes (`taverne`: count sloubis; `foret`: messages are seeds, `#words` grow "microbiotes" with their own encyclopedia; `moulin`: messages turn the mill wheel). Its founder can pick the theme and set a password. The original single room is `/chante`; `/` is the home page where you type a room name. Code comments, UI text, README and TODO are in French; keep that convention.

## Commands

```bash
bin/build.sh                # PRODUCTION deploy: tidy, vet, build, govulncheck, then restart the live systemd service `sloubi`
go run .                    # run locally (127.0.0.1:8888; PORT=..., HOST=0.0.0.0 to expose)
go test -race ./...         # all tests live in src/web/web_test.go
go test ./src/web -run TestRoutes   # single test
go vet ./...
govulncheck ./...           # dependency audit (go install golang.org/x/vuln/cmd/govulncheck@latest)
```

Releases: the `sloubi` binary is not tracked any more (`.gitignore`); each GitHub release (`gh release`, tags `vX.Y.Z`) ships `sloubi-<tag>-linux-{amd64,arm64}.tar.gz` (binary built with `CGO_ENABLED=0 -trimpath`, plus `assets/`, `views/`, `deploy/`, `forbidden.example.json`) and `SHA256SUMS`. The real `forbidden.json` is private and gitignored; `forbidden.example.json` is the public minimum and `TestForbiddenExample` keeps it loadable.

The project targets Go 1.27.3. There is no linter config, no JS build step and no Dockerfile.

The server resolves `assets/`, `views/`, `db/` and `forbidden.json` relative to the **current working directory**, so run it from the repo root (tests `chdir` there in `TestMain`). It refuses to start without a valid `forbidden.json`. `db/chat.sqlite` (WAL mode) is created and migrated on startup and is gitignored.

Production: systemd unit `sloubi` runs `./sloubi` from the repo root (hardening drop-in in `deploy/hardening.conf`: `www-data`, read-only FS except `db/`; anything new that writes to disk must go under `db/` or get its own `ReadWritePaths`), behind Caddy (`/etc/Caddyfile`, reverse proxy to 127.0.0.1:8888). Gin trusts `X-Forwarded-For` only from 127.0.0.1/::1. Rate limits key on `clientKey` (IPv4, or the IPv6 /64).

## Architecture

- `src/web/routes.go` holds the `server` struct (store, hub, forbidden list, one `Limiter` per action) and all routes:
  - Pages: `GET /` renders `views/home.html`. `GET /:chan` renders `views/room.html` for every room with `{{.Chan}}`, `{{.Theme}}` (labels, colour, FX script) and `{{.Locked}}` (no access cookie yet: the page shows the password gate). Uppercase names get a 301 to lowercase; invalid or forbidden names get a 404 that renders the home page with the name prefilled, so it shows red.
  - `GET /_/` renders `views/directory.html` (all rooms, via `Store.listChannels`, cached 15 s in `server.dir*`). It can't collide with a room because the name regex forbids a leading separator; keep that true if the regex ever changes.
  - API: `/api/check/:chan`, `POST /api/:chan/messages`, `GET /api/:chan/last-sloubi`, `POST /api/:chan/postit`, `GET /ws/:chan`, plus `info`, `settings`, `unlock`, `microbiotes[/:tag]` under `/api/:chan/` (in `rooms.go`).
  - Handlers take a `channelResolver`, so the legacy routes (`/verif.json`, `/last-sloubi.json`, `/ws`) reuse the same code, pinned to `chante`.
  - Input hygiene happens here: `application/json` required, 4 KB body cap, length limits. `cleanText` applies NFC, strips control and format characters (bidi, zero-width; ZWJ kept) and caps combining marks at 2.
  - Transport: `http.Server` timeouts (5 s headers), `floodGuard` on every request, a WS cap per key (`maxWSPerKey`), and security headers including a CSP with no inline styles. Use the `hidden` attribute or CSSOM (`el.style.x = …`), never `style="…"` in templates.
  - Nicknames go through `cleanNickname`: NFC, Latin script + ASCII digits + space `_-.'` only, 2–24 runes, `forbidden.json` applied, and "Anonyme" is reserved. Invalid characters are rejected, not stripped. `POST /api/nick` exposes this for `/nick`. A message (or a call join) without a valid nick is refused (`400 nickname required` / `nick-required`); `app.js` turns the input into a nickname prompt until one is set.
  - Room settings apply per control: clicking a theme card posts it at once; nickname and password each have their own « Changer » button (`runButton`: Changer → En cours… → Changé ✓). The server evicts the room *before* answering, so the client sets `reloadDelay` before the request (`postChange`).
  - A room is created on its first message, post-it or settings call, never on a visit. Creation goes through its own rate limit (`mayCreate`).
- `src/web/rooms.go`: themes, owner, password, microbiotes.
  - **Owner:** the request that founds a room gets `ownerKey` once (random; only its SHA-256 is stored in `channels.owner_hash`). The client keeps it in `localStorage` (`sloubi_owner_<chan>`), or adopts it from a `/<chan>#cle=<key>` link. Rooms founded before this feature (`chante` included) have no owner and can't be configured.
  - **Password:** PBKDF2-SHA256 in `channels.pw_hash`, guessed through `lockLimit`. `unlock` sets an HttpOnly cookie `sloubi_k_<chan>` = HMAC(`meta.cookie_secret`, chan + pw_hash), so changing the password revokes every cookie. Every room API route and the WS go through `server.enter`, which answers 403 without access.
  - Theme or password changes call `Hub.Evict`: a `{type:"room"}` event, then every socket in the room is closed; clients reload.
  - Sloubis are only validated in `taverne` rooms. `#tags` are extracted at insert into the `tags` table (backfilled once when the table is created); the Go regex in `extractTags` and `TAG_RE` in `app.js` must stay in sync.
- `src/web/calls.go`: group calls (max 6, P2P mesh), only in password-locked rooms and only for clients that passed `enter`. Audio goes everyone-to-everyone; video is one presenter at a time ("live"): `Hub.stage` holds the room's presenter, `op:"live"` claims a free stage (else `stage-busy`) or releases it, leaving the call releases it, and `roster` carries `live`.
  - Signaling rides the room WebSocket: `readPump` now hands inbound frames (32 KB max, token bucket per client) to `server.onClientMessage`. Call state (`pid`, `nick`, `inCall`, `muted`) lives on `client` under `Hub.mu`; `Hub.calls` maps room → participants. `signal` is relayed only between participants, to the one `to` pid; `roster` goes to the whole room (and to newcomers in `Hub.join`). Dropping a client leaves its call.
  - The newcomer sends the offers (`joined` lists existing peers), so offers never cross.
  - `GET /api/:chan/turn` mints coturn REST credentials (HMAC-SHA1, 6 h) from `TURN_SECRET` or `TURN_SECRET_FILE`, i.e. BeamCam's coturn on the same box (`deploy/turn.conf`). Without a secret it returns STUN only.
  - `Permissions-Policy` allows `microphone`, `camera` and `display-capture` for `self` only.
  - Every peer connection negotiates an empty `sendrecv` video transceiver up front (the offerer adds it; the answerer flips the offered one to `sendrecv`). Going live is `replaceTrack()` on those senders, stopping is `replaceTrack(null)`: no renegotiation (BeamCam's trick). `tune()` caps `maxBitrate` by viewer count; screens get `contentHint = "detail"` and `maintain-resolution`.
  - Spectators join with `listen:true` (no mic: a `recvonly` audio transceiver), can't go live and can't receive a handoff.
  - Handoff: the presenter sends `handoff` to a pid, `Hub.relay` remembers the offer, the target gets `handoff`; its `live on` then takes the stage even though it's held, and the old presenter drops it on the next `roster`. `handoff-decline` tells the presenter.
  - Client: `assets/call.js`, loaded only when `{{.Calls}}`. Chips are rebuilt only when their signature changes, and clicks are delegated on the list: rebuilding (or a hover that resizes a chip) under the pointer swallows clicks. It talks to the socket through `sloubi:send` / `sloubi:call` / `sloubi:ws-closed` window events; `app.js` owns the socket. Losing the socket hangs up.
- `src/web/reactions.go`: links and likes, totals only (nobody is tracked). `extractLinks` and `LINK_RE` in `app.js` must match: the link's order in the message is the click index. `POST /api/:chan/like {id, delta:±1}` (never below 0; the browser remembers its own likes in `sloubi_liked_<chan>`), `POST /api/:chan/click {id, i}`; both broadcast `{type:"like"|"click"}`. The backlog carries `likes` and `clicks`.
- `src/web/files.go`: shared files, locked rooms only (`privateRoom`). `POST /api/:chan/files` takes the raw file as the body (`X-File-Name`, `X-Nickname`, URL-encoded), streams it to `db/uploads/<chan>/<random id>`, classifies it from its first bytes (`classify`: image / video / audio / document; HTML or SVG is always a document), makes a JPEG thumbnail with EXIF orientation applied for jpeg/png/gif, and posts a message carrying `file`. Quota 10 GB per room (`reservations` stop parallel uploads from overshooting) and `diskReserve` keeps 5 GB free on the server disk. `GET /api/:chan/files/:id` serves inline only allow-listed media mimes, everything else as an attachment, with a sandbox CSP; `?thumb=1`, `?dl=1`. `GET /api/:chan/files?kind=` lists them with counts and usage; `GET /api/:chan/favorites[?ids=]`. Uploads and downloads extend the server's 15 s / 30 s deadlines with `http.ResponseController`, which is why `/api/*/files` is excluded from gzip (its writer does not unwrap). Tests set `uploadRoot` to a temp dir.
- `src/web/videolinks.go`: shared links in the library. `sharedLinks` scans the room's messages once: YouTube / Vimeo / Dailymotion links (`videoOf`) go to Vidéos, every other http(s) link to Documents (with its click total). Video titles and thumbnails are fetched by the server (oEmbed + fixed thumbnail URLs, hosts allow-listed even across redirects), cached in `db/vthumbs` and table `video_meta`, retried after a day; `GET /api/:chan/vthumb/:provider/:id` only serves a video actually cited in that room (no open proxy). Browsers never contact those platforms, and `img-src` stays `'self'`. Other links get no preview on purpose: fetching arbitrary member-supplied URLs server-side would be an SSRF risk.
- `src/web/push.go`: Web Push for call starts, stdlib only (RFC 8291 `aes128gcm` encryption with `crypto/ecdh` + `crypto/hkdf`, RFC 8292 VAPID JWT signed ES256; keys in `meta.vapid_private`). Subscriptions in `push_subs (endpoint, channel)`, only for locked rooms, endpoints restricted to known push hosts (`pushHostAllowed`, SSRF). The first `join` of a call returns `started` plus the `tag`s of browsers already connected to the room (sent by `{type:"hello"}`); `notifyCall` pushes to the others, at most once per 90 s per room, and forgets endpoints answering 404/410. `assets/sw.js` is served at `/sw.js` (root scope) and only shows notifications: no `fetch` handler.
  - The in-page ringtone is `assets/ring.js` (random FM/filter/delay patch per call, WebAudio, unlocked on the first click or key).
- `src/web/channels.go`: the room-name regex `^[a-z0-9]+([._-][a-z0-9]+)*$` (max 32 chars) and the `forbidden.json` matcher.
  - Names are normalized before matching: lowercase, separators removed, leet mapped to letters. Then come the `exact` / `allow` / `contains` lists.
  - The list hot-reloads on mtime change; a broken file keeps the previous list.
  - A name containing `.` like `app.js` passes the regex, so every root-level route or file must also be listed in `forbidden.json` under `exact`.
- `src/web/db.go`: `Store` and the migrations (adding `channel` to legacy `messages` with default `chante`, plus the `channels` and `postits` tables).
  - **Sloubi rule:** a message counts only if it matches `sloubi <N>`, N is the room's max + 1, and the `clientId` differs from the previous valid sloubi's author.
  - The check and the insert run under `Store.wmu` inside a transaction, backed by `UNIQUE(channel, sloubi_number)`.
- `src/web/message.go`: the `Hub` keeps rooms → clients. Each client has a buffered `send` channel, and only its `writePump` writes to the conn (gorilla-style conns aren't concurrency-safe).
  - `join` pushes the backlog and the post-it under the hub lock, so clients must dedupe messages by `id`.
  - A full buffer drops the client.
  - WS payloads are `{type:"message", ...flat message fields}` or `{type:"postit", ...}`. `chat.Message.ClientID` is `json:"-"` and is never broadcast.
- `src/web/limiter.go`: a per-IP token bucket with an optional strike-based temporary ban (used for `/api/check`).
- Frontend:
  - Room layout (Nov 2026): a top bar (Sloubi.chat home link · room · small score · ⚙ Options), an always-visible icon nav (`.app-nav`: a row under the bar in portrait, a rail on the left in landscape ≥ 700 px, hidden while the phone keyboard is open; `.room-shell` is a grid with areas bar / nav / main), the thread in a bordered panel (`.thread`), Messenger-style bubbles (`.msg-row.mine` on the right: the client remembers its own message ids in `sloubi_mine_<chan>`, since the server never says who wrote what), day separators, avatars by initial. `.message` keeps the nickname span followed by the body span: the scenes rely on that. `assets/library.js` drives the nav views (`.nav-item[data-view]`: Discussion / Favoris / Images / Vidéos / Documents, file counts as badges, the quota at the top of the media views), the lightbox and the uploader. The nav's « Post-it » item (`#navPostit`, handled in `app.js`) replaces the floating pin, and the open post-it is never placed over the nav (paperclip, drag-and-drop anywhere, paste; XHR for progress, 3 in parallel).
  - `assets/recorder.js` (locked rooms): the « + » next to the paperclip opens a menu (voice message / video) and a recorder dialog. `MediaRecorder` compresses while recording (Opus 32 kbit/s; 720p at 1.2 Mbit/s), with the first supported mime among MP4 (Safari) and WebM. The file is handed to `window.sloubiUpload` (library.js). The name's extension (`.weba`, `.m4a`) tells the server a voice note is audio even though its container sniffs as video (`audioExt` in `classify`). The page CSP has `media-src 'self' blob:`: without it no shared video or audio plays, and blob: is the pre-send review.
  - Mobile keyboard (`assets/viewport.js`, loaded first): iOS pans the page instead of resizing it, so `body.room` is `position: fixed`, the page never scrolls (only `#chatMessages` does), and `.room-shell` takes `--vvh` / `--vvt` from `visualViewport` (modals, menu and lightbox too). `body.kb-open` trims the chrome on phones. The send button keeps the keyboard open (`touchend` + `mousedown` preventDefault), dragging the thread down blurs the input, and `sloubi:viewport` keeps the thread pinned to the bottom if it was. Inputs stay ≥ 16 px (iOS zooms below that). Real-device testing is the only way to check this: no emulator reproduces the iOS keyboard.
  - `assets/app.js` (room page): reads the room from `body[data-chan]`, posts and connects per room, and implements the post-it. Post-it position and open state live in `localStorage` (`sloubi_postit_<chan>`); its text is shared and last write wins.
  - `/nick <pseudo>` is handled client-side in `sendMessage` (nothing gets posted). The client stores the canonical name the server returns.
  - `assets/room-fx.js` + `room.css`: a Three.js scene (vendored at `assets/vendor/three/`, MIT; `three.module.js` imports `./three.core.js`). Procedural textures only, no image assets.
    - It reacts to the `sloubi:message` window event that `app.js` dispatches per rendered message (`detail.live` is false for backlog). Live messages puff smoke; live sloubis fire a spark burst and add `.flare` to the counter.
    - `forest-fx.js` and `mill-fx.js` are the other two scenes, built on `fx-kit.js` (renderer, loop, degrade, reduced motion). They also listen to `sloubi:count` and `sloubi:milestone` (every 10 messages), and the forest reads `detail.tags`. `room-fx.js` stays standalone.
    - Both follow the visitor's local time: `daylight()` in `fx-kit.js` (`day`, `golden`, `dawn`, `dusk`; `?heure=14` forces the hour for testing) and `skyColor(sky, night, day, golden)` blend each colour. The kit sets `body[data-daylight]` (`nuit` / `aube` / `jour` / `soir`), which `themes.css` uses to keep text readable in daylight.
    - The mill's water renders the scene a second time from a mirrored camera (half-res `HalfFloat` target, clipped at the surface, water hidden) and samples it with wave-distorted UVs, plus Fresnel and specular glints. The sky is a shader dome (not `scene.background`) so that it reflects correctly.
    - `cyber-fx.js`, `kawaii-fx.js` and `bd-fx.js` are 2D canvas scenes on `fx2d.js` (stop-motion cadence via `fps`). They also dress the chat through `detail.el` of `sloubi:message`: ransom-note nicknames and decrypting text (cyber), the googly-eyed send button (kawaii), left/right speech bubbles and onomatopoeia stickers (bd). Kawaii and BD are light themes: `themes.css` redefines the text colours and drops the dark text shadows.
    - Themes are declared in `rooms.go` (`themes` + `themeOrder`, which drives the settings cards); counters and ambient lines per theme are the `COUNTERS` table and `ambientMessages` in `app.js`. `TestThemesComplete` checks every theme has its FX file.
    - `themes.css` recolours `room.css` per `body[data-theme]` (CSS variables plus a few gradients), scrollbars included (`--sb-*`). Scrollbars are styled with `::-webkit-scrollbar` for Chrome/Safari and `scrollbar-color` only inside `@supports (-moz-appearance: none)`: Chrome ignores the webkit pseudo-elements as soon as `scrollbar-color` or a non-auto `scrollbar-width` applies. Headless Playwright hides scrollbars; check them with system Chromium (`--headless=new`, without `--hide-scrollbars`).
    - It degrades on slow frames, renders a single static frame under reduced motion, and falls back to the CSS background when WebGL is unavailable (`body.no-webgl`).
    - Headless testing needs Playwright's `chrome-headless-shell` with `--use-angle=swiftshader --enable-unsafe-swiftshader`; system Chromium gets no WebGL there.
  - `assets/home.js` + `home.css` (home page, also the landing): sober, NADAPROD's visual language (paper / warm black from the system theme, one accent colour, Permanent Marker titles, Archivo text, hand-drawn rules from `assets/marker.css`, copied from NADAPROD). Local validation, then a debounced `/api/check`; `body[data-state]` (`ok` / `bad` / `wait` / `empty`) colours the hint. For a locked room without the access cookie (`/api/check` returns `access`), Enter reveals a password field that calls `/unlock`, so you arrive unlocked. The form has two inputs and no submit-only flow, so Enter is handled in JS on both. Only network or server failures may show "le serveur ne répond pas": rendering errors are outside that `try`.
  - The CSP is strict (`script-src 'self'`, `font-src 'self'`), so no inline scripts: pass server data through `data-*` attributes. Fonts are self-hosted in `assets/fonts/`; don't add third-party CSS or fonts.
  - The room page closes its WebSocket on `pagehide` and reconnects on `pageshow` (bfcache). Without that, sockets survive navigation and stall the browser for seconds. Keep this when touching the WS code.
